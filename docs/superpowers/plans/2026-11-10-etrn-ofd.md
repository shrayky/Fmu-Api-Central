# Платформа ОФД как второй оператор ЭТрН

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Central опрашивает входящие ЭТрН грузополучателя в Платформе ОФД и по тем же кнопкам приёмки подписывает титул Т3.

**Architecture:** Тип подключения `ofd` добавляется к уже существующему списку на организации. Вход — API Key в Keycloak, дальше `Authorization: Bearer` на шлюз `transedm`. Список, чтение Т1, запись Т3 и отсоединённая подпись живут в `EtrnOfd` и реализуют тот же `IEtrnOperator`, что Saby. Разбор титула грузоотправителя и сборка титула грузополучателя — общий код в Domain, чтобы ОФД не ссылался на проект Saby.

**Tech Stack:** .NET 10, xUnit, CryptoPro (хеш ГОСТ Р 34.11-94 и отсоединённая CMS), Webix, CouchDB как сейчас.

## Global Constraints

- Живой ОФД, Keycloak и КриптоПро в автотестах не вызываются. HTTP подменяется обработчиком, хеш ключа и подпись — подделкой.
- Регистрация организации агрегатором (поиск по ИНН, оферта ЭДО, XAF) в этот план не входит. Организация в ОФД уже есть, API-ключ ей выдан.
- Протокол Saby этим планом не чинится: плоские тела JSON-RPC и закрытие накладной по старому событию остаются отдельной задачей.
- Сертификат и пароль контейнера по-прежнему только в `TrueApiIntegrationSettings`. API-ключ ОФД — на подключении, `client_id` и `client_secret` — в настройках сервера.
- Токен в CouchDB не пишется и в журнал запросов не попадает. В журнале нет тела входа в Keycloak.
- Опрос: `GET https://api-test.platformaofd.ru/transedm/public/api/v1/etrns?subscriber-id={id}`. Параметр `number` не передаётся: в карточке ЭТрН это номер накладной, не размер страницы.
- В список приёмки попадает только статус `CARGO_ON_WAY`. Документ закрывается, только если тот же id вернулся с другим статусом. Отсутствие id на странице документ не закрывает.
- Подпись Т3 — отсоединённая CMS байт того XML, который ушёл в `PUT .../documents/1110341v5.01`. Тело `PUT .../signature` — эти байты подписи, `Content-Type: application/octet-stream`, не Base64.
- Пустой API-ключ и пустой `client_secret` при сохранении не стирают уже записанные. На экран уходит маска, как у пароля Ветис.

## Вне плана

- Захват организации и подписание оферты ЭДО.
- Исправление `EtrnSabyGateway`: вложенный `Документ` / `Вложение` и закрытие только по последнему этапу документа.
- Замена `ReceiverTitleWriter` у Saby на общий титул Т3.
