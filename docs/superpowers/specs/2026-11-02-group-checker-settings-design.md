# Настройки группы в пакете fmu-api-check

Дата: 2026-11-02

## Цель

При скачивании пакета инстанса рядом с `fmu-api-check.exe` лежат два файла. `config.json` подключает инстанс к Central. `settings.json` — выгрузка настроек FMU-API, заранее загруженная в группу этого инстанса. На первом запуске `fmu-api-check` подставляет её как настройки по умолчанию.

Кнопка «Скачать файл» и «Получить ссылку» собирают один и тот же zip.

## Границы

Входит:

- вложение `settings.json` на документе группы в CouchDB
- статус «Настройки загружены» и кнопки на карточке группы инстансов
- запись `settings.json` в отдаваемый пакет рядом с `fmu-api-check.exe`
- импорт `settings.json` в FMU-API при первом запуске

Не входит:

- установщик `fmu-api.exe --install`
- схема настроек группы и команда «Выгрузить настройки»
- повторное применение `settings.json`, если в `%ProgramData%\Automation\FMU-API` уже есть `config.json`
- показ содержимого файла на карточке

## Слои

**FMU-API-Central, Domain**

- `InstanceGroupView.hasCheckerSettings` — признак, что у группы есть вложение. Тела файла во View нет.

**FMU-API-Central, Application**

- `InstanceGroupManagerService`: загрузка, замена и снятие вложения. `Apply` при сохранении карточки вложение не трогает.
- `CheckerDistributionService`: по токену инстанса пишет оба файла в каталог exe внутри zip.

**FMU-API-Central, Infrastructure / CouchDb**

- вложение с именем `settings.json` на документе группы (`fmu-api-central-instance-group`), тем же способом, что файл обновления ПО. Отдельного строкового поля на `InstanceGroupEntity` нет.

**FMU-API-Central, Presentation**

- `InstanceGroupController`: загрузка и снятие вложения.
- карточка «Группа инстансов», вкладка «Основная».

**FMU-API, Infrastructure / ApplicationConfigurationService**

- `SimpleParametersService` на первом запуске читает `settings.json` рядом с процессом и применяет `SettingsExchange.TryApply`.
- `SidecarConnectionImporter` по-прежнему читает только `config.json`.

## Карточка группы

Место: диалог «Группа инстансов», вкладка «Основная», сразу под полем «Схема настроек». Карточка схемы настроек не меняется. «Сохранить» и «Отмена» остаются внизу.

Файла нет — одна кнопка «Загрузить настройки». Файл есть — статус «Настройки загружены», кнопки «Заменить» и «Убрать». Выбор файла скрытый, один `.json`. Содержимое и имя файла на карточке не показываются.

У новой группы кнопок нет, пока карточку не сохранили. «Сохранить» закрывает диалог, кнопки видны при следующем открытии.

«Загрузить» и «Заменить» шлют файл отдельным запросом, не в теле «Сохранить». «Убрать» снимает вложение. Повторное снятие не ошибка. После успеха статус на открытой карточке обновляется сразу.

## API

- `POST /api/instanceGroup/{id}/checker-settings` — `multipart/form-data`, поле `file`
- `DELETE /api/instanceGroup/{id}/checker-settings`

Тело запроса сохраняется во вложение как есть, после проверки что это JSON-объект.

Ошибки:

- пустой файл, массив, не-JSON — «Файл настроек должен быть JSON-объектом», вложение не пишется
- нет группы — «Группа не найдена»

Central не проверяет набор полей выгрузки FMU-API. Неизвестные поля остаются в файле. При импорте FMU-API берёт только поля с `ExchangeableSetting`.

## Пакет

`CheckerDistributionService.Build` по-прежнему требует публичный адрес и токен инстанса и пишет `config.json` рядом с `fmu-api-check.exe`:

```json
{ "serverAddress": "<публичный адрес>", "token": "<токен инстанса>" }
```

Дальше:

1. У инстанса нет группы, группа не найдена или вложения нет — в пакете только `config.json`. Скачивание успешно.
2. Вложение есть — в тот же каталог, что и exe, пишется `settings.json` байтами вложения. Адрес и токен в него не дописываются.
3. Вложение числится, но прочитать его не удалось — пакет не отдаётся, ошибка «Не удалось прочитать настройки группы».

Шаблон `update.zip` на диске не меняется. Уже лежащий в шаблоне `settings.json` в отдаваемом пакете заменяется вложением группы. «Заменить» на карточке меняет вложение, следующий пакет берёт новый файл. Уже установленный инстанс из-за этого сам не обновляется.

Первый обмен с Central отдаёт настройки, которые инстанс поднял из `settings.json`. Схема группы на них сама не накладывается: она уходит на инстанс только по «Выгрузить настройки».

## Первый запуск FMU-API

Процесс — `fmu-api-check.exe`. `fmu-api.exe` настройки не читает.

`SimpleParametersService` импортирует `settings.json` только если своего `config.json` в `%ProgramData%\Automation\FMU-API` ещё нет. Файл ищется в каталоге процесса. Успешный разбор пишется как настройки по умолчанию через `SettingsExchange.TryApply`.

Нет файла — остаются обычные настройки по умолчанию. Битый JSON или ошибка `TryApply` пишется в лог, служба стартует, в ProgramData остаются настройки по умолчанию. Файл рядом с exe не удаляется.

`config.json` рядом с exe в настройки не переносится. Его читает sidecar и заполняет адрес и токен Central, если они ещё пустые.

Повторный запуск, когда файл в ProgramData уже есть, `settings.json` не читает.

Установщик каталог версии копирует целиком, оба файла доезжают вместе с `fmu-api-check.exe`. Код установщика не меняется.

## Тесты

Central:

- пакет кладёт `settings.json` рядом с exe и оставляет в `config.json` адрес и токен
- без группы и без вложения `settings.json` в пакете нет
- ошибка чтения вложения не отдаёт пакет
- битый файл не сохраняется
- сохранение имени и схемы не стирает вложение
- шаблон `update.zip` на диске после сборки пакета тот же

FMU-API:

- первый запуск применяет помеченные поля из `settings.json`
- `config.json` рядом с exe в настройки не переносится
- при уже существующем `config.json` в ProgramData импорта нет
- битый `settings.json` не затирает настройки по умолчанию
