# DaData: ФИАС торговой точки

Дата: 2026-11-16

Задача: FMU-22.

## Цель

Кнопка «Получить» в окне торговой точки заполняет ФИАС и адрес дома через подсказки DaData. Если при загрузке входящих ЭТрН и ВетИС адрес документа не совпал с адресом точки или её синонимом, по адресу документа через стандартизацию DaData получается ФИАС дома, и поиск точки идёт уже по этому ФИАС.

## Границы

Входит:

- секция `dadataSettings` в `config.json`: флаг «Использовать», API-ключ, секретный ключ
- вкладка «Прочие интеграции» в настройках сервера
- кнопка «Получить» у поля ФИАС в окне точки
- проект `src/Infrastructure/Dadata/Dadata.csproj`: клиенты подсказок и стандартизации
- вызов стандартизации при загрузке ЭТрН и ВетИС и запись синонима

Не входит:

- вызов DaData из браузера
- запись ключей в переносимый файл настроек
- правка уже заполненного `SalePointUid`
- подбор по ФИАС улицы, города или квартиры
- замена адреса накладной строкой DaData

## Слои

Отдельное приложение не создаётся. HTTP-клиенты лежат в новой библиотеке того же решения, по образцу `src/Infrastructure/VetisApi`.

**Domain**

- `DadataSettings` в `Domain.Configuration.Options`: `enable`, `apiKey`, `secret`.
- Поле `dadataSettings` в `Parameters`, рядом с `etrnSettings`.
- Порт разбора адреса. Его реализует `Dadata.csproj`, вызывают сценарии в `Application`.
- `SalePointMatch` не меняется: адрес и синоним по-прежнему сравниваются обрезкой пробелов и без учёта регистра.

**Application**

- Разбор ответа подсказок и ответ стандартизации. HTTP здесь нет.
- Сценарий загрузки вызывает его `EtrnIncomingLoadService` и `VetisIncomingLoadService`.
- Синоним пишется тем же правилом, что `SalePointService.RememberAlias`: не длиннее 250 символов, не перетягивает адрес другой открытой точки, закрытая точка не получает синоним.

**Infrastructure, `src/Infrastructure/Dadata/Dadata.csproj`**

- Два HTTP-клиента в этом проекте. Подсказки: `https://suggestions.dadata.ru/suggestions/api/4_1/rs/suggest/address`, заголовок `Authorization: Token`, `count = 20`. Стандартизация: `https://cleaner.dadata.ru/api/v1/clean/address`, заголовки `Authorization: Token` и `X-Secret`.
- Ключи читаются из `Parameters`.
- Порт объявлен в Domain. `Application` на `Dadata.csproj` не ссылается.
- Регистрация `AddDadata()`.

**WebApi**

- Ссылка на `Dadata.csproj`. В `Program.cs` вызывается `AddDadata()`.
- `POST /api/organization/dadata-address`, тело `{ "address": "..." }`.
- Тот же доступ, что у остальных методов `OrganizationController`.
- Выключенный флаг и пустой API-ключ дают ошибку, запрос в DaData не уходит.
- Ответ — список домов `{ "fiasId", "address" }` либо ошибка. Ключей в ответе нет. Из тела ошибки DaData берётся `message`. Поля `message` нет — «DaData недоступна».

**WebApp**

- Вкладка в `serverSettings`, сохранение через `buildConfigurationUpdaters`.
- Кнопка в `organizationSalePoints.js`. Окно точки само карточку не сохраняет.

## Настройки

Вкладка «Прочие интеграции» в том же окне, что «Сервер», «Ветис» и «ЭТрН». Поля: «Использовать», «API-ключ», «Секретный ключ».

Ключи лежат в `config.json` и показываются на этой вкладке. В `PortableSettings` секции нет.

| Состояние | Кнопка | Загрузка |
| --- | --- | --- |
| Флаг выключен | скрыта | стандартизация не вызывается |
| Флаг включён, API-ключ пуст | ошибка «Укажите API-ключ DaData», поля не меняются | стандартизация не вызывается |
| Флаг включён, секрет пуст | подсказки работают | стандартизация не вызывается |
| Оба ключа есть | подсказки работают | стандартизация вызывается |

## Кнопка

Запрос уходит на `POST /api/organization/dadata-address` с адресом из окна этой точки. Другие точки не смотрятся.

Дом — это непустой `house_fias_id`. Строки без него отбрасываются. Несколько строк с одним `house_fias_id` — один дом.

Текст дома — `unrestricted_value` строки с `fias_level = 8`. Таких строк несколько — берётся первая. Строки уровня дома нет — берётся первая строка с этим `house_fias_id`.

В списке одна строка на дом. Один дом список не открывает: ФИАС и этот текст пишутся в окно сразу. Выбор из списка пишет `house_fias_id` и текст выбранной строки.

Текст длиннее 250 символов — ни адрес, ни ФИАС не меняются, сообщение «Адрес DaData длиннее 250 символов».

Пустой адрес в окне — «Укажите адрес», запрос не уходит. Дома в ответе нет — «Дом по адресу не найден». Сеть, лимит и неверный ключ — текст ответа DaData, а если его нет, «DaData недоступна». Во всех этих случаях поля остаются как были.

## Загрузка документов

ЭТрН передаёт тот же адрес, который уже уходит в `SalePointMatch`: `DeliveryAddress`. ВетИС передаёт адрес площадки предприятия. Пустая строка стандартизацию не вызывает.

Вызов выполняется, когда `SalePointUid` пуст и `SalePointMatch.Find` вернул пусто. Уже выбранная точка повторную загрузку переживает.

В одном проходе загрузки одинаковый адрес, без учёта регистра и краевых пробелов, спрашивается один раз. Следующая накладная того же прохода получает результат из этой памяти. Если первая накладная успела записать синоним, вторая совпадает по синониму и до памяти не доходит.

Стандартизация отдаёт один адрес. Точку ищем только если `house_fias_id` непустой и `qc = 0`. `qc = 3`, `qc = 2`, пустой дом и прочие коды точку не ищут и синоним не пишут.

По `house_fias_id` ищутся открытые точки организации документа. Сравнение — обрезка пробелов и без учёта регистра. Пустой ФИАС точки не участвует.

- По ФИАС ничего не нашлось — у точек без ФИАС каноническая строка DaData (`result`) сравнивается с адресом и синонимами так же, как адрес документа: обрезка пробелов и без учёта регистра. Это другая строка, чем адрес накладной, поэтому поиск до DaData её не закрывает. Точки с заполненным ФИАС в этот поиск не входят. Адрес и ФИАС точки при загрузке не меняются: их правят только из карточки точки.

- Ровно одна точка. Перед записью организация читается заново. Открытая точка с этим uid ещё есть — документу пишется он, синонимом становится исходный адрес документа, не строка DaData. Точки уже нет — uid остаётся пустым.
- Ноль точек или несколько. Документ остаётся без точки, синоним не пишется.
- Адрес длиннее 250 символов или уже указан у другой открытой точки. Uid пишется, синоним нет. Ошибка записи синонима uid не снимает.

Пока синонима нет, каждая новая загрузка накладной с тем же адресом снова вызывает стандартизацию. Ошибка связи и ответ о лимите пишутся в лог. Накладная сохраняется без точки, опрос ЭТрН и ВетИС продолжается.

## Тесты

Код пишется от падающего теста. HTTP DaData в тестах нет: порт возвращает готовый ответ.

`Application.Tests`, разбор ответа:

- несколько строк с одним `house_fias_id` дают один дом и полный адрес строки с `fias_level = 8`
- строки уровня дома нет — берётся первая
- адрес длиннее 250 символов — отказ
- два разных `house_fias_id` — две строки списка
- строка без `house_fias_id` в список не входит
- стандартизация с `qc = 0` и домом отдаёт этот `house_fias_id`
- `qc = 3`, `qc = 2` и пустой дом результата не дают

`Application.Tests`, загрузка ЭТрН и ВетИС:

- совпадение адреса или синонима не вызывает стандартизацию
- выключенный флаг и пустой секрет не вызывают стандартизацию
- уверенный дом и одна открытая точка пишут uid и синоним исходного адреса
- точка исчезла при повторном чтении организации — uid остаётся пустым
- ноль точек и несколько точек с одним ФИАС оставляют uid пустым
- точка без ФИАС подбирается по стандартизованному адресу, точка с другим ФИАС — нет
- неуверенный разбор не подбирает точку по стандартизованному адресу
- заполненный `SalePointUid` не меняется
- адрес длиннее 250 и адрес, уже занятый другой точкой, пишут uid без синонима
- один проход с одним адресом даёт один вызов
- две загрузки без синонима дают два вызова
- ошибка стандартизации сохраняет накладную без точки
- ВетИС передаёт адрес площадки

`WebApp.Tests`:

- выключенный флаг скрывает кнопку
- один дом заполняет ФИАС и адрес
- несколько домов показывают список, выбор заполняет оба поля
- длинный адрес и «дом не найден» оставляют поля как были
- вкладка читает и отдаёт на сохранение флаг, API-ключ и секрет
