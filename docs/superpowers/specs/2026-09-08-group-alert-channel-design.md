# Канал оповещения в группе инстансов

Дата: 2026-09-08

## Цель

Канал оповещения задаётся на группе инстансов. При отправке берём канал группы, если он включён; иначе — глобальный канал из `telegramBotSettings`. Пороги, расписание и шаблоны как сущности остаются глобальными; меняется только куда уходит сообщение и какой набор инстансов видит шаблон.

## Границы

Входит:

- поле `alertChannel` на группе (сущность, View, API, CouchDB)
- резолв канала и фабрика `IMessageService` по `provider`
- разрез стандартных алертов и шаблонов по каналу группы
- вкладки в карточке группы, валидация `isEnabled` + пустой `chatId`
- кнопка «Тест» на карточке группы
- колонка типа канала в списке групп

Не входит:

- перенос порогов / расписания / шаблонов в группу
- вырезание канала из `TelegramBotSetting` (глобальный JSON не мигрируем)

## Слои

**Domain / Bot**

- `AlertChannel`: `isEnabled`, `provider`, `chatId`, `botToken` (те же JSON-имена, что у глобального канала)
- `AlertChannel.Resolve(groupChannel, globalChannel)`: если `groupChannel != null` и `groupChannel.IsEnabled` — группа, иначе глобальный
- `AlertChannel.FromBotSettings(TelegramBotSetting)` — проекция глобального канала
- `IMessageServiceFactory.For(BotProvidersEnum)`

**Domain / InstanceGroup**

- `InstanceGroupEntity.AlertChannel` (по умолчанию выключен: `isEnabled=false`, `provider=telegram`, `chatId=0`, `botToken=""`)
- то же поле в `InstanceGroupView`

Существующие документы CouchDB без `alertChannel` десериализуются в выключенный канал → fallback на глобальный.

**Application**

- `InstanceGroupManagerService`: если `isEnabled` и `chatId == 0` — `Result.Failure`, запись не выполняется
- тест канала группы: принимает `AlertChannel` из формы, шлёт фиксированное пробное сообщение через фабрику; fallback на глобальный канал нет
- `AlertTemplateRunService` и сборка стандартных алертов вызывают `Resolve`, не читают UI

**Infrastructure / Messages**

- в DI регистрируются все три реализации (`TelegramBotService`, `MaxBotService`, `NtfyBotService`)
- фабрика отдаёт сервис по `provider` в момент отправки
- `IMessageService.Send(token, chatId, text)` без изменения контракта

**Presentation**

- диалог группы: `tabview`, ширина ~640, кнопка «Тест» на вкладке канала
- список групп: колонка типа канала
- глобальные настройки оповещений без изменений (их «Тест» по-прежнему бьёт в глобальный канал)

## Резолв канала

Для инстанса:

1. Есть `GroupId`, группа найдена, `alertChannel.isEnabled` — канал группы
2. Иначе — глобальный `telegramBotSettings`
3. Если выбранный канал выключен (`isEnabled=false`) — не отправляем, ошибки нет

«Канал группы задан» = `isEnabled == true`. Пустой `chatId` при включённом канале на отправку не попадает: такую карточку нельзя сохранить.

## Поток отправки

### Стандартные оповещения (`AlertsConstuctor`)

Пороги и расписание — из глобального `TelegramBotSetting`. Сообщения по-прежнему по одному инстансу. Каждое сообщение уходит в резолвнутый канал этого инстанса (фабрика по `provider`, `Send` с token/chatId канала).

### Шаблоны (`AlertTemplateRunService`)

Пороги в `AlertSettingsSnapshot` — глобальные.

- Каждая группа с `alertChannel.isEnabled`: отдельный прогон, в контекст только инстансы этой группы, отправка в канал группы
- Все остальные инстансы (нет группы, группа не найдена, канал выключен): один общий прогон, отправка в глобальный канал
- Если глобальный канал выключен, общий прогон не шлёт сообщения

`GroupId` нужен в снимке инстанса для нарезки (`AlertInstanceSnapshot` или эквивалент в сборке контекста).

## UI

Карточка группы:

- вкладка «Основная»: имя, автообновление, схема настроек
- вкладка «Канал оповещения»: `isEnabled`, протокол (`telegram` / `max` / `ntfy`), chatId, токен; поля канала disabled, пока `isEnabled` снят
- кнопка «Тест» на вкладке канала: шлёт пробное сообщение в канал **из полей формы** (можно до сохранения). Если `isEnabled` снят или `chatId == 0` — ошибка на фронте, глобальный канал не трогаем. API: `POST` с телом `AlertChannel`; тот же текст, что у `/api/BotTest`. Глобальный `GET /api/BotTest` не меняется.

Одно сохранение — обе вкладки в одном `InstanceGroupView`.

Список групп: колонка «Канал» — `telegram` / `max` / `ntfy`, если `alertChannel.isEnabled`; иначе пусто.

Глобальная вкладка «Настройка канала оповещения» остаётся запасной.

## Ошибки

- `isEnabled` и `chatId == 0`: отказ на фронте и в API, частичной записи нет
- тест группы: `!isEnabled` или `chatId == 0` — отказ; ошибка `Send` — текст ошибки в UI
- ошибка `Send` по одному каналу: лог, остальные группы/инстансы продолжают
- неизвестный `provider` в UI нет; в фабрике — `Result.Failure`, без исключения наружу
- в UI только `telegram`, `max`, `ntfy`

## Тесты

Domain:

- `Resolve`: группа включена / выключена / `null` / инстанс без группы
- `FromBotSettings` копирует четыре поля канала

Application:

- Create/Update: отказ при `isEnabled` и `chatId == 0`
- Create/Update: успех при выключенном канале (chatId может быть 0)
- шаблон: группа с каналом — свой прогон и свой chatId; остальные — один прогон в глобальный chatId
- стандартный алерт: два инстанса, разные каналы — два `Send` с разными chatId
- тест канала: `isEnabled` + валидный chatId — `Send` с token/chatId/provider из тела; выключенный или `chatId == 0` — отказ без `Send`

Моки только у `IMessageService` / фабрики / репозиториев, где без них нельзя. Проверяем поведение (куда ушло, какой набор), не число вызовов мока как самоцель.
